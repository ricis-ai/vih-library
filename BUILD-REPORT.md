- `library.js` — search, sort, and grouping logic, adapted from `manuals.js`: same token matching (every query word must match; a word of 3 or more letters matches inside a token), plus `sortLibrary` with five orders (listed, name A to Z, name Z to A, newest first, oldest first) and `groupBySubsection` for the field-reference sections.
- `build_library.js` — the generator that writes `library.json` from the index data. Re-run it with `node build_library.js` after any data change.
- `test_library.js` — 43 checks on the data and the logic. Run with `node test_library.js`.
- `test_page.js` — 33 checks that run the page's own render, search, and sort script under a DOM stub in Node. Run with `node test_page.js`.

## Design decisions

- Renamed names on the page, plain names in the URLs. Field-reference entries show their renamed file names (stamp v2.0-20261116-2218-AB9MZ), matching what members see in group Files, but their download links point into the field-reference repository, which keeps the plain kit names because the selector loads section files by those names. The displayed name and the URL's file name therefore differ for those entries, and the tests assert exactly that.
- The kit zip links to its Facebook Files post (permalink 3039961369670510, the renamed upload from rename batch 1), because the zip is not in the field-reference repository. The entry says so plainly. This link depends on the Facebook copy staying put, so it needs a fresh look once Gregory decides the mirror-versus-delete fork, which is open again after he took back the mirror choice the same evening.
- The two copyright-check files (Tonne article, blind-population PDF) are listed with no download link and the flag "Coming soon — source check pending." Their notes say they are still in the group's Facebook Files.
- The document index is listed as superseded by this page, with no download link. The page is the index now, and a downloadable text copy would go stale the moment it was listed.
- The 46 field-reference Braille and plain-text files are NOT entries in library.json. They are not in the Document Index (they are not in group Files), so the data file stays faithful to its source. The field-reference section links to their folders in the field-reference repository instead, so members can still reach them.
- Empty categories share one section, "Categories with no documents yet", with 22 items (14 empty categories plus 8 government sublevels), each marked "No documents yet." One section instead of 22 near-empty ones keeps the heading list short for screen-reader users.
- Sort behavior: in the default listed order the field-reference sections render grouped, each with its own heading as a skip point, in book order. Under any other sort they render as one flat list in that order, since a sort by name or date cuts across sections. Search results are grouped by section, with the sort applied inside each group.
- The close-button and deep-link scripts are scoped to `a.back-link` only. The manuals page selected every Facebook group link, which would have turned the kit zip download link into a close button. The tests assert the scoping.
- Relative URLs for files that will live in the new library repository (CNTST and LIC folders), so they work whatever the repository is called. Files already on GitHub use absolute Pages URLs.
